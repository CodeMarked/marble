# Documentation Guardrails

## Scope and ownership

- Canonical behavior and policy live in `MASTER_PLAN`, `architecture/*`, `runbooks/*`, `guardrails/*`, and `decisions/*`.
- Working notes live in `notes/*` and are used for active context, open questions, and short-horizon planning.

## Update rules

- Update relevant docs in the same change where behavior, policy, or architecture shifts.
- Record significant architecture decisions in `decisions/*`.
- Keep `MASTER_PLAN.md` aligned with current priorities and open questions.

## Readability rules

- Prefer short sections with direct, concrete wording.
- Use tables for status, ownership, and question tracking.
- Keep each document focused on one topic and link out to related canonical docs.
